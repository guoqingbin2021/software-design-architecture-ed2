# ADR 001 单体事务与学生后教学班锁

> 历史证据位置：本文件记载的evidence路径指原始测试记录.zip内部的相对路径，统一见配套资源包的04_测试与验收。重新执行自检时，当前结果写入工程根目录evidence。

状态：采用。

问题：不同学生会争一个名额，同一学生还会并发选择两个冲突班。只保护教学班会漏掉学生维度的跨班规则，应用进程内锁不能协调多实例。

备选：①只有教学班悲观锁，不能排除跨班课表冲突；②乐观版本，冲突后需在新事务重读并重做全部规则；③统一取得学生锁后取得教学班锁，在READ_COMMITTED事务内查询、检查、写记录和计数。

决定：采用③。选、退及成绩写入均遵守学生→教学班顺序。课程、学分、班级时间在开放后固定；MeetingSlot本章仅一个固定周时段。远程通知不进入持锁事务。

收益：两个竞争维度均被保护，所有本地变更可共同回滚，规则容易复核。

代价：同一学生写操作串行，热门班有锁等待；死锁/超时不是满额错误，重试须建立新事务并重做检查。未经负载测试不声称吞吐量保证。

证据：backend/evidence/green中容量竞争、同学生冲突、成绩退课并发与回滚测试；新连接SQL对比计数和ACTIVE数。关联R02/R03/R06、C01/C02/C05/C06。
